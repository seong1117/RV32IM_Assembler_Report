# 검증 절차와 결과

README의 명령으로 최종 소스를 빌드한 뒤, 예제별로 생성된 `.bin`과 `.lst`를 확인한다. CPUlator에서는 이전 실행 상태를 리셋하고 새 `.bin`을 `0x00010000`에 로드한 뒤 같은 주소에서 실행한다.

## 과제 예제에서 발견한 오류

| 파일 | 증상 | 원인 및 수정 |
| --- | --- | --- |
| `asm_example1.s` 44행 | `invalid number: (1 << IRQ_TIMER) \| (1 << IRQ_KEY)` | 기존 파서는 숫자나 심볼 하나만 읽었다. 괄호와 연산자 우선순위를 처리하는 상수식 파서를 추가했다. |
| `asm_example2.s` | 바이너리는 생성되지만 CPUlator에서 `At pc=fffffffc: Function clobbered register(s): sp` | `jal PUT_STR`이 `ra` 대신 `a0`에 복귀 주소를 써서 복귀 주소와 문자열 포인터가 모두 잘못됐다. `rd=x1`로 수정했다. `0x00010030`의 인코딩은 `1EC0056F`에서 `1EC000EF`로 바뀌었다. |
| `asm_example3.s` 194행 | `invalid number: SCREEN_H * 512 / 4` | 곱셈·나눗셈을 상수식 파서에 포함했다. |
| `asm_example4.s` 587행 | `unsupported escape in "\b \b"` | 백스페이스 이스케이프를 추가했다. `.asciz` 출력에서 `08 20 08 00`을 확인했다. |

## 실행 및 인코딩 결과

- **기본 테스트:** `test_assembler.s`는 정수 곱셈 `6 × 7 = 42`, 상수와 메모리 값 비교, `.bss` 읽기·쓰기를 검사한다. 성공 시 LEDR에 `0x155`, 실패 시 `0x3FF`를 쓰고 정지 루프에 들어간다. 사용자가 CPUlator에서 동작을 확인했다.
- **과제 예제 4개:** 수정 후 모두 `.bin`·`.lst`가 생성됐으며 사용자가 CPUlator에서 동작을 확인했다. 최종 확장판의 `.bin`은 각 예제의 수정 직후 바이너리와 바이트 단위로 일치했다.
- **추가 문법:** `%hi(0x12345FFF)`는 `0x12346`, `%lo(0x12345FFF)`는 `-1`로 인코딩되는지 확인했다. 문자열 종료 바이트 및 정렬 패딩도 비교했다.
- **F·전처리 복합 테스트:** `examples/f/test_f.s`는 인클루드 파일의 매크로를 호출해 두 개의 `flw`를 만든다. F 명령·가상 명령 28개, 지역 라벨 분기 오프셋과 `.float`·`.double`·`.dword` 바이트를 예상값과 대조했다. `0xFEDCBA9876543210`이 `.lst`에서 16자리로 표시되는 것도 확인했다. 이 테스트의 확인 기준은 기계어와 데이터이며 F 명령의 CPUlator 런타임 검증과 구분한다.
